# Seat 3: Motor and alternative input

Keyboard-only, switch access, voice control (Dragon, macOS Voice Control, Windows Voice Access), tremor and limited precision, one-handed use, fatigue and RSI.

**Method.** I read the code on fork main `e1792b9b0` (worktree fork main) and compared it with the 0.1.7 VPAT (the v0.1.7 audit notes (`operable.md`, kept outside the repo), `field.md`). I did not run the app for this report, so each verdict below is "from code" unless it cites the VPAT runs, and the VPAT tested 0.1.7, not fork main. Before any of this goes into a public statement, re-run the VPAT keyboard scenarios (the v0.1.7 audit scenario `operable-*.mjs` (kept outside the repo)) against fork main.

**The "Space always plays" rule** (`timelineHotkeys.ts:44`, UI-14 review) is a deliberate choice. Because Enter now presses buttons it's tolerable, but it does break widgets whose only key is Space: a Radix **checkbox** (WAI-ARIA checkboxes toggle on Space, and Radix blocks Enter) and any focused `role=switch` outside `[data-shape-ui]`. Scope the exception the right way round: Space plays **unless** a focus-visible element whose native key is Space has focus (checkbox, switch, radio, option, `button` reached by Tab). The `:focus-visible` test already used for shape controls (`ShortcutDispatcher.tsx:66-73`) is the seam. A clicked control (`data-click-focus`) keeps Space for Play, so the mouse user's habit is preserved. **Effort S.**

## 2. A separate "precise / keyboard mode", or capabilities everywhere?

### How reference tools handle it

| Tool                | Approach                                                                                                                                                                                                                                              | Lesson                                                                                                                                                                                                         |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Blender**         | No separate mode. Every transform is a modal operator you can type into: `G X 2 Enter` moves 2 units on X. The N panel has typed transforms, F3 searches every operator, and preferences offer emulate-3-button-mouse, emulate numpad and sticky keys | Typing during any gesture is the gold standard: you start a move with a key and finish it with a number.                                                                                                       |
| **Figma**           | No separate mode. X/Y/W/H fields take math (`+16`, `*2`). Arrows nudge 1 px, Shift+arrow 10 px, and the "big nudge" size is a preference. Tab / Shift+Tab walks sibling layers, Enter goes into children, Shift+Enter goes to the parent              | The focus cursor moves through objects (layers), not pixels, and the nudge size is a setting.                                                                                                                  |
| **Logic Pro**       | Every view has a text twin: the **Event List** shows the piano roll as a table, and the Key Commands editor binds anything. VoiceOver works through those tables, not the canvas                                                                      | A list or table view of the same data is the accessible editing surface for a canvas.                                                                                                                          |
| **Reaper + OSARA**  | Everything is an action. Users chain actions into **custom actions (macros)**. OSARA adds speech plus keyboard paths for every edit (item properties dialogs, typed position and length). The community shares keymaps                                | Make actions composable and shareable, and have the community maintain profiles. This is the biggest blind and motor-impaired DAW community, and it was built on top of an action list, not on a special mode. |
| **MuseScore 4**     | A focus cursor on the score moves element to element (Alt+arrows), note input is letters plus duration digits, and F6 moves between panels. Note input is a mode, but navigation, selection and editing are everywhere                                | A focus cursor on the canvas, moving by musical meaning (next note or chord) rather than by pixel.                                                                                                             |
| **Ableton Live 12** | Added Tab/arrow navigation across clips and tracks and screen reader support to the existing UI, with no separate mode                                                                                                                                | Retrofitting into the main UI worked.                                                                                                                                                                          |

### Tradeoff

- **A separate mode** is easy to ship and test on its own, and it never slows down the mouse UI. But it splits the product. Features land in the main UI first and the mode falls behind, so the accessible path is always a release late. Users who switch between mouse and keyboard because of fatigue or bad days lose context. And it goes against "every feature is a command": a mode that keeps a second copy of features is the opposite of that rule. Voice users would also have to know they need to enter the mode first.
- **Capabilities everywhere** costs more up front and needs discipline in reviews, but it follows straight from the existing action registry and command bar. A keyboard user and a mouse user see the same screen, and every new action becomes accessible when it's registered.

### Recommendation: capabilities everywhere, plus an opt-in **Accessibility profile** that changes _parameters_, not _features_

1. **Field focus cursor (Effort M).** Make the field one focusable composite (`role=application`, or a `grid` with `aria-activedescendant`) with a visible focus ring on one marcher. Tab or F6 brings focus into the field. **Alt+arrows** move the cursor to the nearest marcher in that direction (MuseScore uses Alt+arrows; plain arrows stay as nudge). Enter or Space selects (replace), Shift+Enter adds, Ctrl/⌘+Enter toggles. Home/End go to the first/last in drill order, `[`/`]` to the previous/next in drill order (or new keys if speed keeps the brackets). Announce "T3, 4 steps outside right 35, 8 behind front hash" through a polite live region. Seam: `ThreeField.tsx` (tabindex and keydown), `fieldMarchers.ts` (nearest-in-direction query), `selectionRing.ts` (cursor ring), and the readout formatting already in `MarcherEditor` (`xDescription`).
2. **Typed selection in the palette (Effort S–M).** Add a `marchers` palette source: typing `T3`, `T1-T6`, `brass - T4` selects. The grammar is already decided in the taste doc (#377). Seam: `registerPaletteSource` in `shortcuts/palette/sources.ts`.
3. **Typed placement command (Effort M).** `/move` or `/to` with field-language coordinates: `T3 to 4 outside R35, 8 behind front hash`, `selection +2 front`, `center box on 50`. Reuse the X/Y description vocabulary from the Inspector and `fieldProperties` checkpoints. It runs one registered action with typed `params` (`ActionParam`, `commandBar.ts`), so it's one undo step and shows live like shapes do. **Also make the Inspector X/Y fields editable** (they're `disabled` today), with the same parser and Figma-style math (`+2`). Seam: `MarcherEditor.tsx:838-905` and `handleCoordsSubmit` (already stubbed: `coordsFormRef`).
4. **Typed counts (Effort S).** Make Inspector "Counts" an input, add a `setPageCounts` action with `params: [{key:"counts", unit:"count"}]` (the comment in `definitions.ts:31` already uses this as its example), and add Shift+arrow on flag grips to move 4 counts (or one measure). Seam: `PageEditor.tsx:72-81`, `TimelinePageFlagGrips.tsx:477`, `pageFlagMove.commit`.
5. **Keyboard shape handles (Effort M).** While a shape is open, Tab (or a dedicated pair) cycles its handles (`editTargets.ts`, the handle list each kind returns: `a`, `b`, `move`, `radius`, `corner`, …) and arrows move the focused handle using the nudge env. Also add typed endpoints for line and arc (`a`, `b` as field coordinates) to `shapeSteps`.
6. **Field pan and zoom actions (Effort S).** Register `fieldZoomIn`, `fieldZoomOut`, `fieldFit`, `fieldPan{dir}` (bound to ⌘= / ⌘- / ⌘0 and Alt+Shift+arrows or similar), and zoom to the focus cursor. Seam: `field/three/fieldNavigation.ts`, `fieldView.ts`.
7. **Macros (Effort L, later).** Reaper-style custom actions: a saved sequence of action ids plus args, bindable and in the palette. It falls out of the command tree (#357) and is the biggest single win for fatigue and RSI, because one key can stand for a 6-step routine. Park it until #357 resumes.

The **Accessibility profile** (Settings › Input › "Precision and motor") is a group of settings. It's not a separate UI:

| Setting                                                         | Default     | Accessible option                                           |
| --------------------------------------------------------------- | ----------- | ----------------------------------------------------------- |
| Drag start distance (mouse)                                     | 4 px        | 4, 8, 12, 16                                                |
| Marcher hit radius (mouse)                                      | 5 px        | 5, 10, 16, 22                                               |
| Handle reach (mouse)                                            | 6.5 / 10 px | up to 22                                                    |
| Larger timeline grips                                           | off         | on (grips 12→24 px, clip resize 6→16 px, hold bar 10→20 px) |
| Sticky modifiers on desktop (show the modifier pill on desktop) | off         | on                                                          |
| Move pad on desktop                                             | off         | on                                                          |
| Big nudge size                                                  | 4 steps     | 2, 4, 8                                                     |
| Key repeat for nudges                                           | OS          | delay and rate of its own                                   |
| Single-key shortcuts                                            | on          | off (need a modifier)                                       |
| Confirm drags                                                   | off         | "click to pick up, click to drop"                           |
| Notification duration                                           | 4 s         | 10 s / stay until dismissed                                 |

Each row is a parameter that the existing seams already read, so none of it forks feature code. It follows the taste rule _"desktop density and precision are never traded away"_: defaults stay as they are, and these are opt-ins.

## 5. A system to keep this from drifting

1. **Rule in the taste doc and in `apps/desktop/AGENTS.md`:** _"Every pointer gesture names its keyboard or typed equivalent and its single-click equivalent in the PR."_ Add it to the PR template's checklist (User guide / Tablet already exist there).
2. **A registry test** (like the existing `definitions` test that lists actions hidden from the palette): every action with `hiddenFromPalette` or no binding must give a reason, and every pointer-capture component in an allow-list must name the action that stands in for its drag. Seam: `shortcuts/__test__/definitions.test.ts`.
3. **Keyboard-only e2e scenario in CI** (`desktop-browser-e2e`): new file, add 8 marchers, select T3 by palette, type a position, add a page, set 16 counts by typing, place a box by `/`, play, export. Uses `page.keyboard` only and fails on any `MOUSE FALLBACK`. Port the v0.1.7 audit scenario `operable-*.mjs` (kept outside the repo).
4. **An axe pass on the main screens** in the same harness for `button-name`, `link-name` and `label-content-name-mismatch`.
5. **Profile settings live in one store** (`AccessibilityProfileStore`) read by `pointerThresholds`, `Toaster`, MovePad, the modifier pill and `buildKeymap`, so a new gesture gets the accessible values by using the shared seam rather than by remembering to.
6. **Recruit testers:** the Reaper/OSARA and MuseScore accessibility communities are active, and band directors with RSI or tremor exist in every district. One remote session per quarter, recorded through the lab, is worth more than any checklist.
