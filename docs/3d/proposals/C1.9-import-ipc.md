## 1. What it has to wire

| Built pipeline              | Branch                    | Entry points the channels call                                                                 |
| --------------------------- | ------------------------- | ---------------------------------------------------------------------------------------------- |
| Local Library store (C1.6)  | `3d/c1-local-library`     | `openLibraryStore` → `listItems`, `getItem`, `readVersionParts`, `addVersion`, `updateItem`, … |
| Model import (C1.7)         | `3d/c1-model-import`      | `readModelFile`, `importModel(file, { kind, choices })`, `saveModelToLibrary`                  |
| Artwork import (C1.8)       | `3d/c1-artwork-import`    | `inspectArtwork`, `groupByAspect`, `importArtwork(store, request, { pdfRenderer })`            |
| pdf.js renderer (C1.8, Q33) | `3d/c1-artwork-import`    | `createElectronPdfRenderer()`: one hidden sandboxed `BrowserWindow` per open PDF               |
| Artwork templates (C1.12)   | `3d/c1-artwork-templates` | `TEMPLATE_SURFACES`, `templateSurface(id)`, `artworkTemplateFiles(surface, { deflate })`       |
| `sharp` (C1.5)              | `3d/c1-sharp`             | loaded lazily (`import("sharp")`), unpacked from the asar                                      |

Shape of the work, from the pipelines as built:

- The model pipeline is **re-run with the user's choices**: `importModel(file, {})`
  gives the pre-selected one-click result, and each change in the review
  (kind, units, rotate, simplify, a clicked grip, a hand-set slot) runs it
  again. Commit stores the result whose choices match what's on screen.
- The artwork pipeline is **inspect, then import-and-store**:
  `inspectArtwork` stores nothing; `importArtwork` re-probes the file, makes
  the display texture and calls `store.addVersion` itself.
- Neither pipeline reports progress or takes an `AbortSignal`.

## 2. Channels

Rules carried from D-4: every name is hard-coded in the preload; main
validates every payload (zod) and checks the sender; the editor is the only
writer. All channels live under `library:`, following the app's
`namespace:kebab-verb` style (`recent-files:clear-missing`,
`view3d:venue-change-request`).

| Channel                      | Dir                   | Request → response                                           |
| ---------------------------- | --------------------- | ------------------------------------------------------------ |
| `library:import-pick`        | editor → main, invoke | `ImportPickRequest` → `Result<ImportSession \| null>`        |
| `library:import-inspect`     | editor → main, invoke | `ImportInspectRequest` → `Result<ImportInspection>`          |
| `library:import-preview`     | editor → main, invoke | `ImportPreviewRequest` → `Result<BytesPayload>`              |
| `library:import-commit`      | editor → main, invoke | `ImportCommitRequest` → `Result<ImportCommitResult>`         |
| `library:import-cancel`      | editor → main, invoke | `{ sessionId, fileId? }` → `Result<void>`                    |
| `library:import-close`       | editor → main, send   | `{ sessionId }` (frees the session's bytes)                  |
| `library:import-progress`    | main → editor, push   | `ImportProgress`                                             |
| `library:list`               | editor → main, invoke | `{ kind? }` → `Result<LibraryItemSummary[]>`                 |
| `library:get`                | editor → main, invoke | `{ itemId }` → `Result<LibraryItem \| null>`                 |
| `library:read-parts`         | editor → main, invoke | `ReadPartsRequest` → `Result<Record<PartRole, Uint8Array>>`  |
| `library:thumbnails`         | editor → main, invoke | `ThumbnailsRequest` → `Result<(BytesPayload \| null)[]>`     |
| `library:update-item`        | editor → main, invoke | `{ itemId, patch: UpdateItemPatch }` → `Result<LibraryItem>` |
| `library:delete-item`        | editor → main, invoke | `{ itemId }` → `Result<void>`                                |
| `library:add-from-show`      | editor → main, invoke | `AddFromShowRequest` → `Result<AddVersionResultDto>`         |
| `library:size-presets`       | editor → main, invoke | `void` → `Result<SizePreset[]>`                              |
| `library:size-preset-save`   | editor → main, invoke | `{ id?, name, data }` → `Result<SizePreset>`                 |
| `library:size-preset-delete` | editor → main, invoke | `{ id }` → `Result<void>`                                    |
| `library:changed`            | main → editor, push   | `{ itemIds: string[] \| "all" }` after every Library write   |
| `library:template-save`      | editor → main, invoke | `{ surfaceId, format }` → `Result<{ filename } \| null>`     |

Not here: the Starter kit zip (Help ‣ Get the Blender starter kit, C1.13)
gets its own channel when that package lands; drag-and-drop comes later
(spec §2).

### Preload exposure

- **Editor preload** (`preload/index.ts`): a `window.electron.library` object
  with one method per invoke channel and `onImportProgress(cb)` /
  `onChanged(cb)` returning an unsubscribe function, like `onNewShowOpen`.
  Types are imported type-only, as the preload already does for
  `view3d/sync/protocol`.
- **3D View preload** (`preload/view3d.ts`): **nothing**. The 3D View renders
  the show's embedded copies, which it already reads through `sqlRead`
  (D-12: a show is self-contained; rendering never reads the Library). A test
  pins `VIEW3D_API`'s keys so a Library method can't slip in.
- **Main** registers every handler through one `handleEditor(channel, schema,
fn)` helper that drops calls whose `event.sender` isn't the editor's
  `webContents` (reuse `isEditorSender` from `view3dWindow.ts`) and parses the
  payload with the channel's zod schema before `fn` runs.

## 3. Payload types

These live in `src/view3d/library/protocol.ts` (types and zod schemas only,
no Electron imports). Report types are re-exported from the pipelines, not
copied.

```ts
type Result<T> = { ok: true; value: T } | { ok: false; error: LibraryIpcError };

interface BytesPayload {
  mimeType: string;
  bytes: Uint8Array;
}

// ---- pick
type PickPurpose = "any" | "model" | "artwork";
interface PickContext {
  // set by a picker's Import…, absent for Library Import…
  kind?: ModelKind; // Equipment / Prop picker
  surface?: ArtworkSurface; // artwork slot picker
  size?: ArtworkSizeChoice; // the slot's size (spec: "pre-fills kind, slot and size")
}
interface ImportPickRequest {
  purpose: PickPurpose;
  context?: PickContext;
}

type ImportFileType = "model" | "artwork" | "unsupported";
interface ImportFileRef {
  fileId: string; // random, session-scoped; never a path
  filename: string; // basename only
  sizeBytes: number;
  type: ImportFileType; // sniffed from bytes, not the extension
  tooLarge: boolean; // over the limit: shown as Can't import
}
interface ImportSession {
  sessionId: string;
  files: ImportFileRef[];
  context: PickContext | null;
}

// ---- inspect (call again whenever a choice changes)
type ImportInspectRequest =
  | {
      sessionId: string;
      fileId: string;
      type: "model";
      kind?: ModelKind;
      choices: ModelImportChoices;
    }
  | { sessionId: string; type: "artwork" }; // all artwork files in the session at once

interface LibraryMatch {
  // drives "New version of …" / Update or Add as new
  itemId: string;
  name: string;
  builtIn: boolean;
  reason: "kit-item-id" | "filename";
}
type ImportInspection =
  | {
      type: "model";
      fileId: string;
      requestSeq: number;
      report: ModelImportReport;
      sidecar: ModelSidecar | null;
      previewReady: boolean;
      matches: LibraryMatch[];
    }
  | {
      type: "artwork";
      files: {
        fileId: string;
        inspection: ArtworkInspection;
        matches: LibraryMatch[];
      }[];
      aspectGroups: AspectGroup[];
    };

// ---- preview bytes for the modal's canvas
type ImportPreviewRequest =
  | { sessionId: string; fileId: string; type: "model" } // normalized GLB of the last inspect
  | {
      sessionId: string;
      fileId: string;
      type: "artwork";
      page: number;
      maxPx: 256 | 1024;
    };

// ---- commit = a new Version in the local Library
interface CommitMeta {
  name: string;
  tags?: string[];
  license?: LicenseInput;
  itemId?: string;
}
type ImportCommitRequest =
  | {
      sessionId: string;
      fileId: string;
      type: "model";
      kind: ModelKind;
      choices: ModelImportChoices;
      meta: CommitMeta;
      thumbnail?: Uint8Array;
    }
  | {
      sessionId: string;
      type: "artwork";
      files: {
        fileId: string;
        surface: ArtworkSurface;
        pages?: number[];
        size?: ArtworkSizeInput;
        pageSizes?: Record<number, ArtworkSizeInput>;
        meta: CommitMeta;
      }[];
    };

interface AddVersionResultDto {
  outcome: AddVersionOutcome;
  item: LibraryItem;
  versionHash: string;
}
type ImportCommitResult =
  | {
      type: "model";
      report: ModelImportReport;
      saved: AddVersionResultDto | null;
    } // null: not ready
  | { type: "artwork"; reports: ArtworkImportReport[] };

// ---- progress
type ImportStage =
  | "reading"
  | "validating"
  | "decoding"
  | "converting"
  | "rendering-pdf"
  | "writing"
  | "saving";
interface ImportProgress {
  sessionId: string;
  fileId: string | null;
  stage: ImportStage;
  fraction: number | null; // null = indeterminate
  page?: { index: number; count: number };
}

// ---- Library reads and writes
type ReadableRole = "glb" | "sidecar" | "display"; // never "original" or the source
interface ReadPartsRequest {
  itemId: string;
  versionHash: string;
  roles: ReadableRole[];
}
interface ThumbnailsRequest {
  items: { itemId: string; versionHash: string }[];
  maxPx: 128 | 256;
}
interface AddFromShowRequest {
  itemId: string;
  kind: LibraryItemKind;
  name: string;
  tags: string[];
  versionHash: string; // main recomputes it from `parts` and refuses a mismatch
  parts: Record<PartRole, Uint8Array>;
  license: LicenseInput;
  derivedFrom: DerivedFrom | null;
}

// ---- templates
type TemplateFormat = "svg" | "pdf" | "png";

// ---- errors (pipeline rejections are report rows, never errors)
type LibraryIpcErrorCode =
  | "invalid-request"
  | "mixed-selection"
  | "session-expired"
  | "unknown-file"
  | "too-large"
  | "unreadable"
  | "busy"
  | "cancelled"
  | "timeout"
  | "worker-crashed"
  | "pdf-unavailable"
  | "not-found"
  | "read-only"
  | "kind-mismatch"
  | "hash-mismatch"
  | "corrupt"
  | "write-failed";
interface LibraryIpcError {
  code: LibraryIpcErrorCode;
  message: string;
} // message: log text, not UI copy
```

## 4. The flow

```text
editor                          main                               import worker (utilityProcess)
  │ import-pick(purpose,ctx) ──▶ showOpenDialog(editor win)
  │                              stat, size check, sniff type
  │ ◀── {sessionId, files[]}     token → path map (no bytes yet)
  │ import-inspect(file,{}) ───▶ read bytes once (+ .gltf resources)
  │                              ── model ─────────────────────────▶ importModel(file,{kind,choices})
  │ ◀── progress (push) ◀─────── ◀──────────────────── report + glb + sidecar
  │ ◀── {report, matches}        keep last result per (file, choices)
  │ import-preview ────────────▶ GLB bytes → modal canvas (GLTFLoader, no decoders)
  │ (user changes a choice) ───▶ import-inspect again; stale replies dropped by requestSeq
  │ import-commit(choices,meta)▶ same choices as cached? reuse : re-run in worker
  │                              saveModelToLibrary(store) → addVersion → library:changed
  │ ◀── {outcome, item, hash}    (editor then embeds the Version in the show, C1.11)
  │ import-close ──────────────▶ drop session bytes
```

- **Pick.** Main shows the dialog parented to the editor window and returns
  refs only. Bytes are read at the first inspect and **kept in the session**:
  commit stores exactly the bytes that were reviewed (no re-read, so a file
  changed on disk mid-review can't slip past the report). The original kept
  as the Version's `source` is those same bytes.
- **Inspect, models.** The first call passes `choices: {}` and the picker's
  kind if any. A plain Library import with no stamp comes back `needs-kind`;
  the review asks for the kind and calls again. Each call carries a
  `requestSeq`; main answers every call but the editor ignores any reply
  older than its latest, and main doesn't kill the worker for a superseded
  call (restarting costs the WASM init).
- **Inspect, artwork.** One call for every artwork file in the session:
  `inspectArtwork` per file, then `groupByAspect` across them, so the size
  step asks once per distinct aspect. Page pickers and the size step use
  `import-preview` with `maxPx: 256` per page, then 1024 for the big preview.
- **Matches.** Main computes `matches` from the store during inspect: a kit
  `itemId` pre-selects "New version of …" (a built-in's id becomes a user
  copy, per `addVersion`); otherwise a same-kind item with the same
  `originalFilename` offers Update or Add as new.
- **Commit.** A model commit with a report that isn't `ready` stores nothing
  and returns the report. An artwork commit runs `importArtwork` per file in
  order; each file is independent, and on cancel the files already stored
  stay (the Library is append-only and identical bytes reuse the item, so a
  retry is harmless). Every successful write pushes `library:changed`.
- **Sessions.** One open session per editor; a new pick closes the old one.
  A session ends on `import-close`, on a new pick, when the editor reloads or
  closes, or after 30 minutes idle.

## 5. Progress and cancellation

- **Progress** is pushed to the sender only, at most 10 per second. Stages
  are coarse; `fraction` is filled only where it's real (pages of a PDF,
  files of a multi-select). The model pipeline needs a small C1.7 follow-up:
  an optional `onStage(stage)` callback in `importModel`, called between
  steps. No other pipeline change.
- **Cancelling a model job** kills the worker process (`child.kill()`) and
  respawns it on the next request. The pipeline's heavy steps are
  synchronous, so killing is the only reliable stop.
- **Cancelling artwork** sets an `AbortController` that main checks between
  files and pages; an open PDF document is closed, which destroys its hidden
  window. A `sharp` call in flight finishes; its result is discarded.
- **Timeouts:** 120 s per model job (then kill, `timeout`); the pdf.js
  renderer keeps its own 60 s per step.

## 6. Where the pipelines run (approved, Q46, recorded in D-13)

**Recommendation: the model pipeline and template generation run in one
`utilityProcess` "import worker"; the artwork pipeline, the pdf.js
renderer, the Library store and every file dialog stay in main.**

Why the model pipeline leaves main:

- `gltf-validator`, the Draco and meshopt WASM decoders, the meshopt
  simplifier and gltf-transform's weld/dedup/prune all run **synchronously on
  the JS thread**. In main that freezes the event loop for seconds on a big
  file: every IPC reply (both windows' `sql:proxy`, the 3D View's
  `view3d:clock` relay, menus, the window controls) stalls.
- A hostile or huge file that crashes or runs out of memory takes down only
  the worker, which respawns. `worker_threads` (as `export-utility-process.ts`
  uses) share main's process and heap, so they don't give that.
- WASM in a utility process is outside the renderer's CSP, so D-15 ("no
  `'wasm-unsafe-eval'`") still holds as written.
- The worker loads `sharp` for texture downsizing. Utility processes are
  plain Node with asar support; packaged checks must confirm both `sharp`
  from `app.asar.unpacked` and Draco's WASM from the asar (the open point in
  C1.7's log).

Why artwork stays in main:

- pdf.js needs a `BrowserWindow`, which only main can create (Q33). Its
  rendering already happens in that window's own renderer process.
- `sharp` does its pixel work on libuv's thread pool, off main's JS thread;
  the synchronous parts (sniffing, pHYs, the SVG header) are small.
- `importArtwork` writes the store itself, and main is the store's single
  writer.

Templates go to the worker because the floor PNG (up to 8,192 px on the
long edge) is a synchronous encode plus `zlib.deflateSync`; SVG and PDF are
cheap but share the path.

Mechanics: a new Vite entry `electron/main/import-worker/index.ts` →
`dist-electron/main/import-worker.js`; spawned on first use with
`utilityProcess.fork(path, [], { serviceName: "OpenMarch import" })`; exits
after 60 s idle; one job at a time (queue). Messages are `{ jobId, op,
input }` / `{ jobId, ok, output | error }` plus `{ jobId, stage }`; byte
arrays are copied (utility `postMessage` transfers only ports), which is fine
at the sizes below. The worker never sees a path and never writes the
Library: main reads the files, sends bytes, and stores what comes back.

## 7. File dialogs

- Main owns every dialog, parented to the editor window (a sheet on macOS).
  The renderer never passes dialog options.
- Filters by purpose, first one selected:
  - `model`: "3D model (glb, gltf)" `[glb, gltf]`, "All Files" `[*]`
  - `artwork`: "Artwork (png, jpg, svg, pdf)" `[png, jpg, jpeg, svg, pdf]`,
    "All Files"
  - `any` (Library Import…): "Models and artwork" (all seven extensions),
    then "3D model (glb, gltf)", "Artwork (png, jpg, svg, pdf)", "All Files".
    The combined filter comes first because macOS greys out every file the
    selected filter excludes (found in owner testing, 2026-10-12).
- `openFile`, plus `multiSelections` for `artwork` and `any`. The start folder
  is the last import folder, kept by main in the settings store.
- A file picked through "All Files" is typed by sniffing (glTF magic or JSON,
  `sniffArtworkFormat`); anything else is an `unsupported` row shown as Can't
  import with the supported formats, not an error.
- Template downloads use `showSaveDialog` with `defaultPath:
<last folder>/<surface.id>.<format>` and one filter for that format.

## 8. Security

- **Paths never come from the renderer.** `library:import-pick` is the only
  way a path enters, and it stays in main's session map
  (`sessionId → { senderId, files: fileId → { path, size, type, bytes? } }`).
  Ids are `crypto.randomUUID()`. A request with an unknown or foreign
  session or file id gets `session-expired` / `unknown-file`.
- **`.gltf` resources stay beside the file.** `readModelFile` follows any
  relative URI, so `../../.ssh/id_rsa` resolves outside the folder and its
  bytes would land in the stored source. C1.7's `container.ts` now resolves
  each URI with `realpath` and refuses anything outside the `.gltf`'s folder,
  reported as `missingResource` (Q55, done in `d3cd28e7`).
- **Size limits** (Q48), checked with `stat` before reading and again on
  the bytes: a model with its resources 200 MB; an artwork file 300 MB (plus
  C1.8's 1.5-gigapixel limit); 50 files per pick; renderer-supplied bytes
  (`add-from-show`, `thumbnail`) 64 MB per call, thumbnails 1 MB.
- **Renderer-supplied bytes** are accepted on two channels only.
  `add-from-show`: main recomputes the Version hash from `parts` and refuses
  a mismatch, decodes the sidecar with its schema, and `addVersion` applies
  the usual built-in-copy rule. `thumbnail`: re-encoded by `sharp` to a PNG
  at most 256 px, so main never stores what the renderer sent verbatim.
- **Every payload is parsed with zod**, strict objects (unknown keys
  refused), string lengths capped (name 200, tag 64, 32 tags, license text
  4 KB), ids checked with the store's own UUID and sha256 schemas.
- **Reads are narrow:** `library:read-parts` serves `glb`, `sidecar` and
  `display` only. Originals and sources never cross IPC (rendering never
  reads originals, D-12); the print master is rendered in main at export.
- **Messages** carry basenames only, never absolute paths.

## 9. Library images in the renderer (approved, Q49, recorded in D-15)

**Recommendation: IPC bytes turned into `blob:` URLs, not a custom
protocol.**

- The editor calls `library:read-parts` (`display`, `glb`) or
  `library:thumbnails` and makes object URLs, as the app already does for
  the field image and audio. Revoked when the query drops the data.
- The CSP sets only `script-src` and `worker-src`, so `img-src` and
  `connect-src` are open and both options work today with **no CSP
  change**. If `img-src` or `connect-src` is ever tightened, `blob:` must be
  listed.
- Why not `om-library://`: the editor and the 3D View share the default
  session, and a `protocol.handle` callback can't tell which window asked,
  so the read-only 3D View could read the whole Library (against D-3 and
  D-12). It also needs `registerSchemesAsPrivileged` before `ready`. Its
  win, streaming and HTTP caching of immutable hashes, doesn't matter at C1's
  sizes.
- `library:thumbnails` batches up to 50 items per call. Artwork thumbnails
  are the `display` part resized by `sharp`; model thumbnails follow Q50.
  Both are cached in `userData/library/cache/thumbs/<versionHash>-<px>.png`,
  outside manifests and the Version hash, safe to delete.
- Revisit a protocol (on a dedicated partition) only if the Library reaches
  hundreds of items and the panel feels slow.

## 10. Template downloads (C1.12)

`library:template-save { surfaceId, format }`: main checks `surfaceId`
against `TEMPLATE_DOWNLOADS` (the template surfaces plus sag, sagging-bottom
and 4 × 8 ft sheet variants; owner, 2026-10-12, Q66), shows the save dialog, has the worker run
`artworkTemplateFiles(surface, { deflate: zlib.deflateSync })` and keep the
requested format, and writes the file. Returns the saved basename, or `null`
if the dialog was cancelled. One format per click (Q53). Uniform part
templates are surfaces like any other, carrying C1.12's wrap note.

## 11. Window lifecycle

The pdf.js renderer's hidden windows count as windows. On Windows and Linux
the app quits on `window-all-closed`, which doesn't fire while a hidden PDF
window is alive, so closing the editor mid-PDF-import leaves a windowless
app running for up to the renderer's 60 s timeout. So: on the editor
window's `closed` (and on `before-quit`) main cancels every import session,
closes open PDF documents (destroying their windows) and kills the import
worker. Hidden windows are never shown or focused, so the export code's
`getFocusedWindow()` is unaffected; `open-win`'s `getAllWindows()` loop
must skip them if it's still around.

## 12. Errors

Handlers never throw across IPC (Electron flattens thrown errors into
"Error invoking remote method …"); they return `Result<T>`. Pipeline
rejections are report rows, not errors (D-22). IPC errors show inline on the
review with Try again, never an `AlertModal`. `worker-crashed` respawns the
worker on the next call; the session's bytes survive in main. `LibraryError`
codes map one-to-one (`invalid-input` becomes `invalid-request`).

## 14. Decisions

Approved by the owner on 2026-10-12, each as recommended.

- **Q45, channel set (D-13):** the 19 channels in §2, all under `library:`,
  with the editor as the only caller and nothing on the 3D View preload. The
  table is copied into D-13. Not an `import:` prefix (it reads like the
  previous-dots import) and not a generic `library:call(op, payload)` (it
  breaks D-4's hard-coded names).
- **Q46, where the pipelines run (D-13):** the model pipeline and template
  generation run in one `utilityProcess` import worker; artwork, pdf.js, the
  store and every dialog stay in main (§6). Not everything in main (it
  freezes all IPC on a big model) and not `worker_threads` (no crash
  isolation).
- **Q47, session tokens and reviewed bytes:** the renderer only holds random
  session and file ids; main reads the bytes once at the first inspect and
  commits exactly those bytes; one session per editor; 30 min idle expiry.
- **Q48, size limits (spec §2):** 200 MB per model with its resources;
  300 MB per artwork file plus the 1.5-gigapixel limit; 50 files per pick;
  64 MB per renderer-supplied payload; 1 MB per thumbnail. An over-limit file
  shows as Can't import, not an error.
- **Q49, Library images (D-15):** IPC bytes turned into `blob:` URLs, with
  batched thumbnails cached under `userData/library/cache/thumbs/`. No custom
  scheme: a protocol handler can't tell the 3D View from the editor.
- **Q50, model thumbnails (D-12):** the review modal captures a 256 px PNG
  from its canvas at commit; main re-encodes it into the thumbnail cache,
  outside the Version and never synced. Missing thumbnails (built-ins, "Add
  to my Library") fall back to the kind icon.
- **Q51, artwork preview raster:** a small C1.8 follow-up,
