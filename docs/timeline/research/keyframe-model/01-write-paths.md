# Every path that writes timeline rows

This lists the writes to `timelines`, `timeline_transitions`, `timeline_assignments`,
`timeline_slot_destinations` and `timeline_kept_assignments` at fork PR #332's head (9dc1fc171).
Paths are relative to `apps/desktop/src/`.

The definitions K1–K3 are in the [README](README.md):

- **K1:** motion ends (today);
- **K2:** stored row ends;
- **K3:** K2 plus start keyframes.

A **stray** keyframe is one the designer didn't ask for. The test is the defined-coordinates rule
"coordinates never stand in for intent" (`docs/timeline/research/defined-coordinates/05-model-sparse.md:62`).

Ground rules found on the way:

- Only these files write the tables directly:
  - `db-functions/timelines.ts`
  - `timelineTransitionsInTransaction.ts`
  - `timelineAssignments.ts`
  - `timelineKeptMarkers.ts`
  - `timelineMembership.ts`
  - `timelineAssignmentEdits.ts`
  - `timelineCommands.ts`
  - `timelineMoveNames.ts`
  - `timelineSplitAtBeat.ts`
  - `timelineSplitMoves.ts`
  - `timelineResize.ts`
  - `timelineRipple.ts`
  - the converter, and `electron/database/convertOnOpen.ts:227`
- Everything under `src/timeline/` routes into those. No SQL trigger writes them; the triggers
  only check rows and log them (ADR 0012 §2).
- The one implicit write: deleting an assignment cascades to its kept marker
  (`electron/database/migrations/schema.ts:542-555`).
- **No path writes a row to fill a gap.** A marcher with no row holds. So every **start
  keyframe** (K3) is a row start that some edit left after a hold.
- Shared, multi-member transitions are written only by these, plus slot edits of an existing
  shared transition:
  - the converter;
  - Split at playhead's first half;
  - `createTrack` with a shape, which has no production caller;
  - cast, which also has no production caller.
    Every Keep, Unset, Basic or Expert add makes the marcher's own one-slot transition
    (`db-functions/timelineMembership.ts:163-187`).

## The table

Notes on the columns:

- **Who:** _D_ = the designer asked for this row; _B_ = written on the designer's behalf as a side
  effect.
- **Zero motion:** whether the path can write a row that goes nowhere.
- **Gap:** whether it can leave a hold before the new row's start, which is a start keyframe
  under K3.

## What the table says

1. **Under K1, every zero-motion row the designer asked for is invisible:** C1, E1, E3, S1, and
   F2's second half. Only Page N's walking kept move (C3) is invisible too. K1 is coordinate-led
   in both directions.
2. **Under K2 and K3, the stray keyframes come from four writers, all on the designer's behalf:**
   - **F1:** Basic's return move ends at the flag.
   - **F6:** Basic splits every move at a new flag.
   - **D2:** Remove keyframe's own stays. The owner made these visible deliberately on
     2026-10-20, so they may count as wanted.
   - **G1:** the converter, once.
     Each is defensible in Basic's page-shaped world. None is defensible under the movie-editor
     rule that removing or adding a key never creates another key elsewhere.
3. **Three writers make keyframes depend on storage rather than on the command:**
   - **E3:** a drag back clears an own page move but keeps a zero-motion slot in a shared move.
   - **S1:** Set to previous page deletes some marchers' rows and writes stays for others.
   - **F4:** a Basic merge deletes the zero-motion rows that follow it.
     The same gesture leaves a hold keyframe for some marchers and none for others. Under K2 this
     is visible on the timeline.
4. **Start keyframes (K3) appear wherever these paths leave a hold before a move:** D1, D2, D3,
   E2 windows, H1, H2, I2, J1, and the converter. Most are designer actions whose result, a hold,
   is today invisible.
5. **Any own move can turn into an invisible pin under K1.** D2 is the clearest case: an edit
   that puts the earlier page back on the stay's destination makes the stay go nowhere. It still
   blocks carry-forward, but it has no diamond, Remove can't reach it, and the keep chain shows
   "own", so Follow again isn't offered (`timeline/timelineKept.ts:48-59`). E6 and C3-style
   destination edits can do the same. K2/K3 make it a visible, removable hold keyframe.
6. **Expert Split page (inspector, `components/inspector/PageEditorUtils.ts:54-70`) may compress the
   page's move into its first half.** This is a suspected bug, read from the `GridEdgeMap` rule in
   `timelineRipple.ts:253` and not run. It would create a start keyframe at the new flag. It is
   worth a test before any keyframe work.
