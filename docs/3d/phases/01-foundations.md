### P1.1: World mapping in core

- Owner: claude-p1.1 (3d/p1-world)
- Status: in-review
- PR: https://github.com/AlexDumo/OpenMarch-timeline/pull/57
- Parallel: yes
- Depends on: —

Add `packages/core/src/field/world.ts` and export it from `@openmarch/core`: `stepMeters`, `pixelsToWorld`, `worldToPixels`, `stepsToWorld` and `fieldFootprint` (design §2). Unit tests use the real templates (HS, college and NFL with end zones, one indoor grid, SoundSport) and check the round trips, the footprint of a football field with end zones (`x ±54.86`, `z -48.77..0` within 1 cm), and that the front sideline maps to `z = 0`.

### P1.2: Venue settings storage

- Owner: claude-p1.2 (3d/p1-venue-storage)
- Status: claimed
- PR: none
- Parallel: yes
- Depends on: —

Add the zod schema and defaults in `src/view3d/core/venueSettings.ts` (ADR D-5, design §3), the `view3d_venue` table in `schema.ts` with a migration generated by the repo script (inspect the SQL before accepting it), `src/db-functions/view3dVenue.ts` (read, and write with `transactionWithHistory`), and `src/hooks/queries/useVenueSettings.ts`. Tests: schema accepts and rejects; `defaultVenueForField` for each template family; a missing row reads as the default without writing; a write followed by undo and redo, against a real database (history tests).

### P1.3: 3D View window shell

- Owner: none
- Status: open
- PR: none
- Parallel: yes
- Depends on: —

Create `electron/main/view3dWindow.ts` (open or focus, close with the editor or show, frameless, secure `webPreferences`), `electron/preload/view3d.ts` with `sqlRead` (main rejects anything but `SELECT` or `WITH`) and `hello`, the vite and electron-builder wiring for the second preload, the `?view=3d` switch in `src/main.tsx` with a dynamic import of `src/view3d/window/View3dRoot.tsx`, and a root that renders the `TitleBar` and an R3F `<Canvas>` with a placeholder ground plane. Add the editor's "Open 3D View" toolbar button and View menu item (ui.md UI-1), and the `view3d:open` channel. Don't build the sync channels; that's P1.4.

### P1.4: Sync protocol

- Owner: none
- Status: open
- PR: none
- Parallel: no
- Depends on: P1.3

Implement ADR D-4 and design §7: `src/view3d/sync/protocol.ts` (types and `showTimeAt`, with unit tests for play, pause, rate and out-of-order `seq`), the relays in `view3dWindow.ts` and the preload, `view3d:window-state`, `useView3dPublisher` mounted in the editor, and `view3dSyncStore` in the window. Venue-change requests are validated and written by the editor through P1.2's hook. If P1.2 hasn't merged yet, build against its documented API and leave a TODO that the reviewer checks. Include a small debug readout in the placeholder root that shows the window's show time, for the e2e test and for manual checks.
